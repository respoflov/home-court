## 검증 질문

> iOS PWA에서 실시간 GPS 러닝 추적이 가능한가? 특히 **화면이 꺼진 동안에도 위치가 들어오는가?**

사전 웹 조사에서 자료가 엇갈렸기 때문에(된다/안 된다 양쪽 보고 존재) 실기기 확인을 선행함.

## 결과 — 불가능 (조건부 가능)

### 정상 동작한 것

- 위치 권한 획득 (Safari 탭에서 미리 허용해두면 standalone에서도 유효)
- Screen Wake Lock 획득 성공 (iOS 18.4+ 조건 충족)
- 위치 정확도 **6~20m** — 실외 GPS 정상 범위, 러닝에 사용 가능한 수준

### 실패한 것 — 백그라운드 완전 정지

| 백그라운드 구간 | 길이 | 수신 |
|---|---|---|
| 15:32:26 → 15:34:28 | 122초 | 0회 |
| 15:35:11 → 15:35:35 | 24초 | 0회 |
| 15:35:59 → 15:37:01 | 62초 | 0회 |
| 15:37:17 → 15:37:41 | 24초 | 0회 |
| **합계** | **3분 52초** | **0회** |

**앱 자체 집계**: 8.7분 / 87회 수신 / 108m / **최대 무수신 공백 125.8초**

복귀 순간 `+13.7m`, `+14.4m` 같은 점프가 찍히지만, 이는 실제 경로가 아니라 **두 지점을 잇는 직선**이다.

### 대안 해석 검증

1. **iOS가 백그라운드 위치를 모아뒀다 일괄 전달하는 것 아닌가?**
   → 아님. 복귀 직후 fix들(#50~52, #69~72)이 전부 복귀 시각에 증분 1m 미만으로 찍힘. 밀린 경로가 쏟아진 흔적 없음.
2. **로그 기록이 지연됐을 가능성은?**
   → 없음. 로그는 위치 콜백 시점 시각으로 기록됨. 백그라운드 구간에 기록된 줄이 0개이고, `[화면 꺼짐/백그라운드]` 태그도 전체 로그에 0개.

### 전경 구간 거리 정확도 — 판단 유보

fix 간 이동이 6초당 1m 안팎이라 대부분 정지 상태였던 것으로 보임. 실제 걷기·달리기 상태의 거리 정확도는 이 로그로 알 수 없음. 필요하면 별도 재측정.

## 제품 결정

- **시간 기반 걷기-달리기 프로그램을 주력으로 확정** — 거리 측정이 불필요해 100% 동작
- GPS는 **선택 기능**으로 부착. 시작 전 "화면을 켜고 앱을 앞에 둬야 기록됩니다" 명시
- 앱이 **백그라운드 공백을 자동 감지해 기록에 표시** — "이 구간 N분은 화면이 꺼져 있어 직선으로 추정됨"
- **거짓 거리를 사실처럼 보여주지 않는 것**을 이 기능의 원칙으로 함
